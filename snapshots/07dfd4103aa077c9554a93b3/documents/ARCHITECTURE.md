# Forge architecture

Forge is an experimental systems language exploring safe ownership, lightweight concurrency and native performance. These are design goals; complete memory safety is not implemented.

## Native compilation

Source .fg → lexer → parser / AST → source module loading → semantic checks → optimizer → C generation → system C compiler / linker → executable.

| Area | Source | Responsibility |
|---|---|---|
| Driver | compiler/main.c, compiler/driver.c | CLI, paths, native toolchain invocation |
| Parsing | compiler/lexer.c, compiler/parser.c, compiler/ast.c | Tokens, declarations and syntax |
| Modules | compiler/module_loader.c, compiler/mod_registry.c | Source imports and standard function mapping |
| Semantic checks | compiler/semantic.c | Visible names/types, initialization, function flow and scoped ownership-send checks |
| Optimization | compiler/optimize.c | Constant folding and expression simplification |
| Native output | compiler/codegen.c | C code and partial ownership diagnostics |
| Browser output | compiler/codegen_js.c | JavaScript functions and 64-bit BigInt operations |
| Runtime | forge-runtime repository | Worker scheduling, mailboxes, events and ownership primitives |
| Standard APIs | forge-stdlib repository | Native I/O, strings, networking and other builtins |
| Bootstrap | bootstrap/compiler.fg | Self-hosted subset compiler; fixed-point verification |

--check parses, loads modules, runs the stage0 semantic checks and optimizes. Its visible-signature and initialization checks are not a complete type or ownership checker. There is no complete borrow-checking or IR verification phase in this pipeline.

The [design principles](docs/design-principles.md) require optimizations to preserve
observable behavior, including traps and resource failures. Guarded specializations
retain checked fallbacks, and proof scans have bounded compiler costs.

Semantic checking and JavaScript emission share pass-owned function indexes.
They defer auxiliary allocation until searches spend a bounded probe budget,
preserve declaration/namespace order, and release their storage when the pass ends.
Semantic checking uses the same deferred-index policy for constant declarations.
That index caches names, while each initializer is still checked at its original
point of use in the current scope and flow state. It is freed before optimization
can rewrite the initializer AST.
Semantic checking and native emission also use a private local-name stack index.
Its push/pop protocol restores outer bindings after shadowing; types and flow or
ownership state remain in the current binding array. Unpromoted small/cheap
stacks stay linear; promoted indexes remain active until the stack reaches zero
and reuse scratch capacity across functions in one pass.

## Execution model

OS worker threads execute lightweight Forge processes through an M:N scheduler and work-stealing queues. Coroutines are cooperative state machines generated by the C backend. Long-running coroutine bodies must yield. Mailboxes use synchronization; await registers descriptors with the event loop (epoll on Linux, kqueue on macOS, select on Windows).

The scheduler mutex orders queue publication, claims and completion accounting.
Its private queue heads, counts, publication and claims share that ownership
interval, so owned queue operations omit a redundant inner mutex. Standalone
queue operations retain their mutex. Both paths use one structural core with a
literal locking policy, and separate archive objects preserve standalone linkage.
Selection order and user-code execution boundaries stay intact.
Retiring the last task through a failed queue publication also wakes completion
waiters, even when no worker received that task.

Runtime factories return a fully initialized owner or NULL. Construction failure
releases partial resources before exposing the object or changing the coroutine
arena provider. The C backend's generated process entry points check scheduler, process and
supervisor creation before body initialization, releasing prior owned objects on
failure. Coroutine spawn allocation failure frees the unattached state and
terminates explicitly, following the generated state's existing allocation policy.
Borrowed supervisor child registration preserves its previous list on failed
growth; its void API remains best-effort and requires exclusive configuration.

Supervisor declarations register restart policy; automatic fault recovery is not implemented. Large task counts need reproducible workload and stability tests before making scaling claims.

## Browser and platform

The JavaScript backend supports functions, enums, source modules, control flow and native main. Native processes, coroutines, structs and linking native archives are rejected.

The separate forge-platform repository contains a React/TypeScript/Tailwind website, a Forge registry backend, a Forge package manager and a checksum-verified installer. The Playground compiles the real parser/optimizer/JS generator to WebAssembly. Compilation runs in a disposable browser worker; generated code runs in a worker inside an opaque-origin sandboxed iframe. Code does not run on the public server. This browser subset has no native concurrency or OS services.

PostgreSQL/Web/Browser are independent modules. Backend routes, SQL and authorization remain in .fg source; native bridges provide protocol, crypto, OS and resource primitives.

## Verification boundaries

- CTest verifies compiler/runtime examples and regressions.
- The bootstrap fixed point verifies deterministic output for a documented subset, not equivalence with the complete C compiler.
- Lean proofs model abstract expressions, not full compiler/runtime memory or concurrency safety.
- API/installer/browser checks run in isolated resources before publishing.
- Performance reports include source, environment, commands and raw data.
- Local dependency candidates use explicit source overrides. A tested published
  revision must be pinned before default clean builds include a dependency fix.
