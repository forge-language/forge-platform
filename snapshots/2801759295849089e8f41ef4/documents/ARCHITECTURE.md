# Forge architecture

Forge is an experimental systems language exploring safe ownership, lightweight concurrency and native performance. These are design goals; complete memory safety is not implemented.

## Native compilation

Source .fg → lexer → parser / AST → source module loading → optimizer → C generation → system C compiler / linker → executable.

| Area | Source | Responsibility |
|---|---|---|
| Driver | compiler/main.c, compiler/driver.c | CLI, paths, native toolchain invocation |
| Parsing | compiler/lexer.c, compiler/parser.c, compiler/ast.c | Tokens, declarations and syntax |
| Modules | compiler/module_loader.c, compiler/mod_registry.c | Source imports and standard function mapping |
| Optimization | compiler/optimize.c | Constant folding and expression simplification |
| Native output | compiler/codegen.c | C code and partial ownership diagnostics |
| Browser output | compiler/codegen_js.c | JavaScript functions and 64-bit BigInt operations |
| Runtime | runtime/ | Worker scheduling, mailboxes, events and ownership primitives |
| Standard APIs | stdlib/, include/ | Native I/O, strings, networking and other builtins |
| Bootstrap | bootstrap/compiler.fg | Self-hosted subset compiler; fixed-point verification |

--check parses, loads modules and optimizes. It is not a complete type or ownership checker. There is no complete borrow-checking or IR verification phase in this pipeline.

## Execution model

OS worker threads execute lightweight Forge processes through an M:N scheduler and work-stealing queues. Coroutines are cooperative state machines generated by the C backend. Long-running coroutine bodies must yield. Mailboxes use synchronization; await registers descriptors with the event loop (epoll on Linux, kqueue on macOS, select on Windows).

Supervisor declarations register restart policy; automatic fault recovery is not implemented. Large task counts need reproducible workload and stability tests before making scaling claims.

## Browser and platform

The JavaScript backend supports functions, enums, source modules, control flow and native main. Native processes, coroutines, structs and linking native archives are rejected.

The separate forge-platform repository contains a React/TypeScript/Tailwind website, a Forge registry backend, a Forge package manager and a checksum-verified installer. The Playground compiles the real parser/optimizer/JS generator to WebAssembly. Compilation runs in a disposable browser worker; generated code runs in a worker inside an opaque-origin sandboxed iframe. Code does not run on the public server. This browser subset has no native concurrency or OS services.

PostgreSQL/Web/Browser are independent modules. Backend routes, SQL and authorization remain in .fg source; native bridges provide protocol, crypto, OS and resource primitives.

## Verification boundaries

- CTest verifies compiler/runtime examples and regressions.
- The bootstrap fixed point verifies deterministic output for a documented subset, not equivalence with the complete C compiler.
- Lean proofs model abstract expressions, not full compiler/runtime memory or concurrency safety.
- API/installer/browser checks run in isolated resources before publishing.
- Performance reports include source, environment, commands and raw data.
